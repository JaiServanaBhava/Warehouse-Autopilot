## 🎯 What Is Warehouse Autopilot?

**Warehouse Autopilot** is an AI-assisted warehouse operations and order-fulfillment platform designed to move beyond passive dashboards.

Instead of simply displaying inventory problems, the system analyzes warehouse state, identifies operational risks, prioritizes actions, provides reasoning, and connects critical events to automated communication workflows.

### Core operating loop

```text
LIVE WAREHOUSE DATA
        │
        ▼
┌─────────────────────┐
│   Decision Engine   │
│ Detect • Rank • Score│
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│    Recommended      │
│      Actions        │
└──────────┬──────────┘
           │
     ┌─────┴─────┐
     ▼           ▼
  Execute      Notify
     │           │
     ▼           ▼
 Inventory    Email / WhatsApp
 & Orders     / Supplier PO
```

## 🏆 Why It Stands Out

Traditional warehouse software often focuses on **visibility**.

Warehouse Autopilot focuses on **operational response**.

| Traditional WMS Approach | Warehouse Autopilot |
|---|---|
| Displays historical or current problems | **Detects and prioritizes operational risks** |
| Manual analysis | **Ranked action queue** |
| Manual alerting | **Automatic notification workflows** |
| Manual supplier reorder process | **Supplier purchase-order generation** |
| Generic chatbot experience | **Warehouse-aware Gemini Copilot** |
| Separate operational functions | **Unified command center** |
| Desktop-first workflows | **Responsive interface for any screen** |

> **Design principle:** the dashboard should not only tell a warehouse team *what is wrong* — it should help them understand *what to do next*.

# 🎤 Judge Pitch

### Problem

Warehouses can have the right data but still react too slowly to shortages, delayed orders and operational bottlenecks.

### Solution

Warehouse Autopilot continuously turns warehouse state into prioritized operational decisions.

### Innovation

Instead of stopping at dashboards or chatbots, the platform connects **detection → reasoning → action → communication → traceability**.

### Technology

Built with **FastAPI, Python, SQLite, Vanilla JavaScript, Server-Sent Events, Gemini 2.5 Flash and Twilio communication workflows**.

### Impact

The goal is to reduce the time between **an operational problem appearing and the right person taking action**.

---

## 1. 🧠 Autonomous Decision & Action Engine

The Decision Engine evaluates warehouse conditions such as:

- Inventory runway
- Stock availability
- Order deadlines
- Customer priority
- Zone bottlenecks
- Worker capacity

It produces a **ranked, executable action queue**.

Each recommendation can include:

- 📌 Exact recommended action
- 💰 Estimated financial loss avoided
- 🎯 Confidence score
- 🔍 Reasoning behind the recommendation
- ⚡ One-click execution

### Example

```text
┌──────────────────────────────────────────────────────────────┐
│ PRIORITY ACTION QUEUE                                        │
├──────────────────────────────────────────────────────────────┤
│ 🔴 CRITICAL  97%  Reallocate KB-303 → Save ₹34,000  [APPLY] │
│ 🟠 HIGH      89%  Reorder MS-201 → Prevent stockout  [APPLY] │
│ 🟡 MEDIUM    74%  Rebalance Zone C → Reduce pick time [APPLY]│
└──────────────────────────────────────────────────────────────┘
```

---

## 2. 📧 Automated Critical-Event Notification Fan-Out

When a critical warehouse event occurs — such as a stockout, SLA risk, or QC failure — the platform can trigger configured communication workflows.

```text
CRITICAL EVENT
     │
     ├──────────────► 📧 Business Email
     │
     ├──────────────► 💬 WhatsApp Alert
     │
     └──────────────► 📦 Supplier Purchase Order
```

Example event:

```text
STOCKOUT DETECTED
SKU: KB-303
Available Units: 0
Orders at Risk: 12
Estimated Exposure: ₹67,000
```

The notification workflow is designed to operate without requiring a user to manually compose every alert.

The **Notification Outbox** provides delivery status, timestamps, and recipients for operational traceability.

---

## 3. 🤖 Gemini 2.5 Flash Warehouse Copilot

A dedicated AI workspace powered by **Google Gemini 2.5 Flash** and grounded in warehouse context.

The Copilot can work with operational information such as:

- Current stockouts
- At-risk orders
- Operational health
- Autopilot score
- Zone congestion
- Worker assignments

### Quick actions

```text
[ 🚨 What should I do now? ]
[ 📉 Critical Shortages ]
[ 📦 At-Risk Orders ]
[ 🗺️ Rebalance Workers ]
[ 📦 Draft Reorder PO ]
```

Conversation history is retained locally so the user can continue the workflow across page refreshes and interface interactions.

---

## 4. 📱 QR Intelligence Passport

Each product can have a scannable QR-based information passport.

A product passport can expose:

- Live stock quantity
- Reserved quantity
- Damaged quantity
- Usable quantity
- Estimated days until stockout
- Reorder recommendation
- Inventory status
- Warehouse location
- Supplier
- Unit price

### Reality Check

If inventory changes after a QR label is generated, the system can identify the label as:

```text
⚠️ QR OUTDATED
```

and provide a regeneration workflow.

This helps floor teams distinguish between a printed label and the current warehouse state.

---

## 5. 🗺️ Live Fulfillment Pipeline

Track the order lifecycle from picking through dispatch:

| Stage | Operational Information |
|---|---|
| 🎯 **Picking** | Bin route, SKU allocation, assigned picker |
| 📦 **Packing** | Carton recommendation, weight, packing material, scan status |
| 🔍 **Quality Control** | Inspection checklist, pass/fail status, exception creation |
| 🚚 **Dispatch** | Carrier, AWB tracking ID, dock bay |

Example picking route:

```text
A07 → B02 → C01
```

# 🚀 Quick Start

## Option A — Deploy with Render

### 1. Fork / clone the repository

```bash
git clone https://github.com/your-username/warehouse-autopilot.git
cd warehouse-autopilot
```

### 2. Install dependencies

```bash
pip install -r requirements.txt
```

### 3. Configure environment variables

Create your backend environment file using the project's environment example.

```env
GEMINI_API_KEY=your_gemini_api_key
GEMINI_MODEL=gemini-2.5-flash

TWILIO_ACCOUNT_SID=your_twilio_sid
TWILIO_AUTH_TOKEN=your_twilio_auth_token
TWILIO_EMAIL_FROM=your_email_sender
TWILIO_WHATSAPP_FROM=whatsapp:+1xxxxxxxxxx
TWILIO_WHATSAPP_TO=whatsapp:+91xxxxxxxxxx
TWILIO_CONTENT_SID=HXxxxxxxxxxxxx

COMPANY_EMAIL=your_company_email
SUPPLIER_PO_RECIPIENT=supplier_email

AUTOMATIC_EMAIL_ENABLED=true
AUTOMATIC_WHATSAPP_ENABLED=true
```

**Never commit real credentials to GitHub.**

### 4. Start the application

```bash
uvicorn backend.server:app --reload --port 8000
```

Open:

```text
http://localhost:8000
```

# 🔐 Security & Production Notes

Warehouse systems can process commercially sensitive information. Before production deployment:

- Store secrets in environment variables or a dedicated secret manager.
- Do **not** commit `.env` files containing real credentials.
- Rotate API keys and authentication tokens if they are exposed.
- Restrict notification recipients and administrative settings.
- Use HTTPS in deployed environments.
- Add authentication and authorization before exposing operational controls publicly.
- Validate external webhook/event payloads.
- Log operational events without exposing secrets or unnecessary personal data.
